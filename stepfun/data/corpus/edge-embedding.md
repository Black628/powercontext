# 端侧向量化与知识库检索

## 为什么要端侧推理

在浏览器里跑 embedding 模型，文档不需要离开用户设备，隐私与延迟都更友好。
模型首次从 CDN 下载并缓存到浏览器 Cache Storage，之后离线也能用。

## 量化方案怎么选

FP32 是基线，体积最大、精度最高。
INT8（q8）体积约压到四分之一，WASM 后端上速度明显更快。
FP16 体积约减半，配合 WebGPU 可以走半精度矩阵乘法，适合有独显的设备。
选择哪种取决于设备：有 WebGPU 优先 fp16，否则用 wasm + q8。

## 推理后端

WebGPU 通过 navigator.gpu 探测，可用时把 device 设为 webgpu。
不可用时必须优雅降级到 WASM，并在界面上明确告诉用户当前后端，
否则用户会以为是模型变慢了。

## 检索链路

导入：读取文件 → 切片 → 批量向量化 → 写入数据库 → 刷新索引。
查询：输入文本 → 向量化 → 数据库混合检索 → 展示原文与打分。

刷新索引这一步容易漏。向量索引多为异步维护，写入后不刷新，
新文档可能短时间内查不到，看起来像"增量导入失效"。

## 性能优化点

批处理比逐条推理快很多，因为矩阵乘法的并行度更高。
模型加载只发生一次，要把加载耗时和推理耗时分开统计。
查询路径上，向量化通常在几十毫秒，数据库检索往往更快，端到端延迟主要看前端渲染。
