# 验证样例：五步看清「会翻旧账」

目标：不依赖任何隐藏状态，按顺序做完就能同时看到三件事 —— Dify 编排在跑、账本真的写进了 PowerContext、新会话真的把旧账翻出来。

## 0. 初始状态

- PowerContext 已启动：`curl http://127.0.0.1:8000/health/ready` 返回 `ready`；
- DSL 已导入，两个 LLM 节点已绑定可用模型，`pc_base_url` 指向 PowerContext；
- 选一个**没用过的玩家 ID**，本样例用 `cui`（换任何名字都行，只要四步都用同一个）；
- 此时该 ID 的账本应为空。可以先确认：

```powershell
python dify/scripts/memory_audit.py --player cui     # entries (0)
```

## 1. 第一次照面：作恶

- 操作：新建对话，玩家 ID 填 `cui`，发送

  > 我把你柜上的青瓷碗摔了，一文不赔

- 预期表现：
  - 掌柜古风口吻回应（动作描写 + 台词），不知道你是谁，语气看热闹不嫌事大；
  - 回复末尾面板：`【恩怨账本 · cui】第 1 次照面 · 怨气 0/100`，`共 0 条：冒犯0／人情0／秘密0／闲话0`；
  - 后台：这一回合被判为 `offense` 并写入 PowerContext。

- 核对：

```powershell
python dify/scripts/memory_audit.py --player cui     # entries (1)，kind=offense，正文含"青瓷碗"与你的原话
```

## 2. 新会话：第一次翻旧账（核心验收点）

- 操作：**不要接着上一段对话**，点「新对话」，玩家 ID 仍填 `cui`，发送

  > 我又来了，上次的碗钱……

- 预期表现：
  - 掌柜**主动提起**青瓷碗这件事（这是 `pc_prepare` 检索到旧账、注入提示词的结果）；
  - 面板变成：`第 2 次照面 · 怨气 25/100`，`共 1 条：冒犯1／人情0／秘密0／闲话0`；
  - 语气比第一次冷，开始要债。

> 只要这两条成立，就说明「跨会话记忆」是 PowerContext 提供的，而不是 Dify 自带的多轮上下文 —— 新会话的 Dify 上下文是空的。

## 3. 赔罪：人情减怨气

- 操作：新对话，同一个 ID，发送

  > 上次的事是我不对，我赔你三坛酒。

- 预期表现：
  - 判为 `favor`，写入账本；
  - 面板显示 `第 3 次照面 · 怨气 50/100`，`共 2 条：冒犯2／人情0`（这一笔还没落账）；
  - 注意：面板算的是「这一笔落账前」的状态；这一笔人情（−18）落账后，下一次照面会变成 32。

## 4. 再看一次：怨气回收

- 操作：新对话，同一个 ID，发送

  > 掌柜的，你这客栈开多少年了？可有旧相好？

- 预期表现：
  - 面板：`第 4 次照面 · 怨气 32/100`（= 25 + 25 − 18），`共 3 条：冒犯2／人情1`；
  - 掌柜会顺口损你两句（"账还没清，倒先打听起我的旧相好了"之类）；
  - 这一回合若判为 `neutral`，账本再添一条闲话，怨气不变。

- 核对：

```powershell
python dify/scripts/memory_audit.py --player cui     # entries (4)，changes 里能看到每次 add 与 reason
```

## 5. 恢复初始状态（重放样例前）

任选一种：

```powershell
# A. 把这位客人的账本全部 retire（PowerContext 保留历史 revision）
python dify/scripts/reset_player.py --player cui

# B. 直接换一个没用过的玩家 ID
```

reset 之后再从第 1 步开始，面板数字会与上面完全一致。

## 判分点对照

| 验收项 | 本样例中的体现 |
| --- | --- |
| 能运行 | 导入 DSL、绑定模型、填 `pc_base_url` 后即可对话 |
| 能体验主要功能 | 第 1–4 步完整覆盖「作恶 → 记仇 → 赔罪 → 怨气变化」 |
| 技术结合有效 | 第 2 步的新会话翻旧账只能来自 PowerContext；第 4 步的面板数字可由 `memory-audit.log` 对账 |
| 过程可复现 | 固定玩家 ID + `reset_player.py` 即可从空账本重放；无隐藏数据 |

## 备注

- 面板数字是确定性的（只由账本里的 `kind` 决定）；掌柜的台词由模型生成，不要求逐字一致，只要求**提到旧账的具体细节**、古风、120–200 字、结尾三个选项。
- 如果模型把「赔罪」判成了 `neutral`，第 4 步怨气会显示 50 而不是 32 —— 这不是流程错误，是判定模型的分类差异；可在 `judge` 节点提示词里补一句「赔礼、还钱、送礼都算 favor」再试。
