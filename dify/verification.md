# 验证样例（按步骤执行）

> 目标：证明「Dify 编排 + seekdb + PowerContext」确实跑通，且**记忆能跨会话复用**。
> 其中样例 1–2 不依赖 Dify，本机已实测；样例 3 需要在 Dify 里跑（步骤见 §3）。

## 1. 设定检索（seekdb 全文索引）

| 项 | 内容 |
| --- | --- |
| 输入 | `POST /lore/search {"query": "规矩", "limit": 2}` |
| 预期 | `count = 2`，命中「酒馆规矩」「赊账规矩」两条，`text` 里能看到规则原文 |
| 实测 | `200 命中 2`，标题分别为「赊账规矩」「酒馆规矩」 |
| 证据 | 网关日志 `[lore] query=规矩 hits=2`；SQL 为 `MATCH(content) AGAINST(... IN NATURAL LANGUAGE MODE)` |

> 这一步证明 **seekdb 承担了"设定库"职责**：NPC 说话的设定依据来自这里，而不是模型编造。

## 2. 记忆写入与召回（PowerContext）

### 2.1 写入

| 项 | 内容 |
| --- | --- |
| 输入 | `POST /mem/remember {"player": "测试玩家-01", "text": "点了招牌酒三更醒，说下次带朋友来。"}` |
| 预期 | `ok = true`，返回 `scope_id` |
| 实测 | `{"ok": true, "scope_id": "scp_3wb2e9xa5gfhjzfeb6pgd24213"}` |

### 2.2 召回

| 项 | 内容 |
| --- | --- |
| 输入 | `POST /mem/recall {"player": "测试玩家-01", "query": "我上次点了什么"}` |
| 预期 | `count ≥ 1`，`text` 里出现"三更醒" |
| 实测 | 第一次 `count=3`，再写一条后 `count=4`（记忆累加） |

### 2.3 演示玩家「阿狸」

| 项 | 内容 |
| --- | --- |
| 输入 | `POST /mem/recall {"player": "阿狸", "query": "杯子"}` |
| 预期 | 召回 1 条：`阿狸上次来店里…摔了一个杯子，答应下次赔一个新的。` |
| 实测 | `count=1, source=search`（**走的是语义检索，不是兜底列表**） |

## 3. 在 Dify 里的完整体验（跨会话记忆复用）

> 需要先把 DSL 导入 Dify（见 `README.md` §五.4）。

**会话 A（第一次）**

1. 打开应用对话页，变量「玩家」填 `阿狸`
2. 输入：`老板，来杯酒`
3. 预期：老陈嘴硬招呼，可能提到"你上次摔了个杯子"
4. 证据：Dify 运行日志里「召回记忆」节点返回 `count=1`；「写入记忆」节点返回 `ok=true`

**会话 B（新开一个对话，模拟隔天再来）**

1. 仍填「玩家」= `阿狸`
2. 输入：`我上次是不是砸了东西？`
3. 预期：老陈直接翻旧账（"杯子，还没赔"），**而不是**反问"什么杯子"
4. 证据：本次会话的「召回记忆」节点 `count ≥ 2`（含会话 A 写入的那条）

**会话 C（换一个玩家）**

1. 「玩家」填 `新客人甲`
2. 输入：`我上次是不是砸了东西？`
3. 预期：老陈不认识他 → "你谁啊？第一次来吧"，**不会**把阿狸的事安到他头上
4. 证据：该玩家 `count=0`，`source=none`

> 会话 A→B 证明记忆被写入并复用；会话 C 证明记忆按玩家隔离，不是全局胡说。

## 4. 异常与降级（可主动验证）

| 场景 | 怎么造 | 预期表现 |
| --- | --- | --- |
| PowerContext 没起 | 停掉 8001 的进程 | `/mem/recall` 返回 `count=0, source=error`，对话仍能继续，不 500 |
| seekdb 没起 | 停掉 2881 | `/lore/search` 返回 `count=0`，NPC 少一点设定依据但仍能聊 |
| 记忆索引未就绪 | 刚写入立刻检索 | 自动退化为最近记忆（`source=recent`） |
| 模型没配 | DSL 里模型名不存在 | Dify 报模型错误；按 `README.md` §五.4 换成可用模型 |
