# 周边去哪儿：基于高德的地点推荐助手

把「附近有什么值得去的地方」变成**有路线数据支撑的推荐**。

一句话说清这个 Skill 的唯一命门：

> **回答里出现的每一个米数、每一个分钟数，都必须来自某一次 `maps_direction_walking` 的返回。**

一旦出现「大概 10 分钟」「直线距离约 800 米，走过去约 12 分钟」「半径 1200 米，步行约 15 分钟」这类推算，就是编造。评分里「数据真实性」占 40%，编一个数就可能把这一项直接打穿。

---

## 一、能力边界

| 要做的事 | 用这个工具 |
|---|---|
| 地名 → 坐标（用户只给地名、没给坐标时） | `maps_geo` |
| 在起点附近按类型找地点 | `maps_around_search` |
| POI id → 坐标 / 地址 / 类型（**必须的一步**） | `maps_search_detail` |
| **步行距离与时间（唯一来源）** | `maps_direction_walking` |

⛔ **明确不用的**：

- `maps_distance` —— 它算的是两点间距离测量，**不是步行路径**。用它算出来的时间一律无效。
- `maps_direction_driving` / `maps_bicycling` / `maps_direction_transit_integrated` —— 本题只要步行。
- `maps_text_search` —— 它按关键词在**城市范围**里搜，不是「起点附近」。用它找出起点几十公里外的店，再硬说成「附近」，是数据真实性问题。只有在周边搜索连续两次都返回 0、且用户愿意放宽时，才作为兜底，并且**必须在回答里写明「这是全城搜索的结果，不是周边结果」**。

## 二、工具参数（严格照此填写）

### `maps_around_search` —— 周边搜索（主入口）

| 参数 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `location` | ✅ | string | 中心点坐标，**格式「经度,纬度」**，经度在前 |
| `keywords` | ❌ | string | 搜索关键词，如「咖啡馆」 |
| `radius` | ❌ | string | 搜索半径，**字符串形式的米数**，如 `"1200"`；不传默认 1000 |

⚠️ `radius` 要传字符串类型的**米数**：`"1200"` 表示 1200 米，`"5000"` 表示 5 公里。不要传 `5`（那是 5 米，什么都搜不到）。

**返回**：

```
{
  "pois": [
    { "id": "B0FF...", "name": "...", "address": "...", "typecode": "050500", "photos": [...] }
  ]
}
```

🔴 **返回里没有坐标。** 这是本题最容易被忽略的一环：周边搜索只给 `id/name/address/typecode/photos`，**必须再调 `maps_search_detail` 才能拿到 `location`**。

### `maps_search_detail` —— 查坐标（不可跳过）

| 参数 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | ✅ | string | 上一步 `pois[].id` |

**返回**：`{ id, name, location, address, business_area, city, type, alias, photos }` —— `location` 就是「经度,纬度」。

### `maps_direction_walking` —— 步行路线（唯一合法时间来源）

| 参数 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `origin` | ✅ | string | 起点，**「经度,纬度」** |
| `destination` | ✅ | string | 终点，**「经度,纬度」** |

**返回**：

```
{ "route": { "origin": "...", "destination": "...",
    "paths": [ { "distance": "620", "duration": "540", "steps": [...] } ] } }
```

- `distance` —— **米**，字符串
- `duration` —— **秒**，字符串

`paths` 是数组，取 **`paths[0]`**。这两个字段是字符串，用之前先转数字再比较，别拿字符串比大小。

### `maps_geo` —— 地名转坐标

| 参数 | 必填 | 说明 |
|---|---|---|
| `address` | ✅ | 结构化地址或地标名 |
| `city` | ❌ | 限定城市 |

⚠️ 这个实现**只把 `address` 传给地理编码接口，`city` 参数并不参与请求**。所以地名有重名风险时，要**把城市名拼进 address**：传 `address="杭州西湖文化广场", city="杭州"`，而不是 `address="西湖文化广场", city="杭州"`。

**返回**：`{ "return": [ { location, level, city, district, street, ... } ] }` —— 数组，可能多条。`level` 说明匹配精度（「兴趣点」「门牌号」「道路」等）。

## 三、执行流程（五步，顺序不能变）

### 第 1 步：把用户那句话拆成五个槽位

例：「我在杭州西湖文化广场，想找咖啡馆，步行不超过 15 分钟，最多 3 家，优先近的。」

| 槽位 | 值 | 缺了怎么办 |
|---|---|---|
| **起点** | 西湖文化广场（或已给坐标） | 必问。不要假设 |
| **城市** | 杭州 | 用户没说就看起点名里有没有；仍没有则问 |
| **地点类型** | 咖啡馆 | 必问 |
| **步行上限** | 15 分钟 | 用户没说 → **按 15 分钟**，并在回答里写明「按默认 15 分钟」 |
| **数量上限** | 3 家 | 用户没说 → **按 3 个**（题目硬上限就是 3） |
| **排序偏好** | 优先近的 | 默认按步行时间升序 |

### 第 2 步：拿到起点坐标

- 用户**已给坐标**（评测时会给）→ 直接用，确认是「经度,纬度」这个顺序，不要翻译成「纬度,经度」。
- 用户**只给地名** → `maps_geo(address="<城市><地名>", city="<城市>")`。
- 返回多条时，按 `level` 选精度最高的（「兴趣点」/「门牌号」优先），并在回答第一句写明「起点按『XX』计算」，让用户能当场纠正。
- `return` 为空 → 换一种写法再试一次（加城市名、去掉门店后缀）；仍为空就告诉用户没定位到，**不要随便找个同名地点顶替**。

### 第 3 步：搜索候选

```
maps_around_search(location=起点坐标, keywords=地点类型, radius="<见下>")
```

**半径怎么定**：

```
搜索半径(米) = 步行上限(分钟) × 80，向上取到 100 或 500 的整数
```

80 米/分钟是**偏快**的步行估计，作用是「宁滥勿缺」地把候选圈进来，**不是**用来算时间的。

- 15 分钟 → 1200 米，传 `"1200"` 或 `"1500"`
- 10 分钟 → 800 米，传 `"900"`
- 5 分钟 → 400 米，传 `"500"`

⚠️ 这个半径**只决定搜多大范围**。最终是否「步行 15 分钟内」，只看 `maps_direction_walking` 的 `duration`。

**候选处理**：

- 按 `typecode` 剔除明显不符的（要咖啡馆却搜出便利店、奶茶店）。
- 保留 **6–8 个**进入下一步。别一次查 20 个，调用数会爆。
- 返回 0 → 半径翻倍再搜一次（`"1200"` → `"2400"`）；还 0 → 走第五节的「无结果」处理。

### 第 4 步：逐个查真实步行路线（**这步不能省**）

对第 3 步留下的每个候选，**两步一对，成对执行**：

```
① maps_search_detail(id=候选.id)                        → 拿 location
② maps_direction_walking(origin=起点, destination=location) → 拿 distance / duration
```

**筛选规则**：

- 🔴 只保留 `duration ≤ 步行上限 × 60` 秒的地点。15 分钟 = 900 秒。**超时的一律不进推荐表，哪怕只超 20 秒。**
- 🔴 某地点 `maps_search_detail` 没返回 `location` → **跳过它**，不要拿它 `address` 去反推坐标，也不要用周边搜索的半径估时间。
- 🔴 `maps_direction_walking` 失败（返回 Error）→ 这一个地点标「路线查询失败」，**不要给它填任何时间**。失败的如果多到不够数，按「服务异常」处理。
- `paths` 是空数组 → 当作「无法步行到达」，跳过。

**额外修一次起点**：如果第 3 步的周边搜索在半径内搜到了候选，但走到每个候选都超过上限，通常是起点坐标本身有偏差。可以核对一下 `maps_direction_walking` 返回的 `route.origin` 是否等于你传进去的坐标，确认没被改写。

### 第 5 步：排序并输出

**排序**：

- 用户说「优先近」/「近一点」/ 没说 → **按 `duration` 升序**
- 用户说的偏好是高德不返回的维度（安静、人多不多、好不好吃）→ ⛔ **不能用它排序**。按时间升序排，然后在理由里注一句「安静程度未核实」

**输出格式（表格 + 一句说明）**：

| 地点 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
|---|---|---|---|---|
| XX咖啡（XX店） | XX路 XX 号 | 620 米 | 约 9 分钟 | 步行时间最短，沿XX路直行可达 |

表下一行说明，例如：

> 起点按「西湖文化广场」计算；共查询 6 个候选，其中 4 个在 15 分钟步行范围内。营业状态与排队情况未核实，建议出发前电话确认。

**写作纪律**：

- 米数直接用 `distance`，不要四舍五入到百位以上（620 就写 620）。
- 分钟用 `duration ÷ 60` 四舍五入到整数。**9 分 10 秒写「约 9 分钟」，不要写「9.2 分钟」。**
- 理由只能引用可查数据：时间最短、距离第二近、地址门牌号明确、`type` 显示是咖啡馆。⛔ 不写「环境优雅」「人气很高」「口碑很好」。
- 最多 3 个。用户要 5 个也只给 3 个并说明「按最多 3 个推荐」。

## 四、五种特殊情况（必须如实说明）

### ① 符合条件的地点不足 3 个

如实说数量：**「在步行 15 分钟内只找到 2 家」**。

⛔ **不要为了凑数把超时地点放进来。** 凑数是这一类题最常见的失分点，评审判据写得很明确：超时地点不能列为「符合条件的推荐」。

如果还想帮用户，可以**另外真的查一次**更大范围，再补一句：「把上限放宽到 20 分钟可多出 1 家」。这句只有在真的又查过之后才能说。

### ② 一个都没找到

说清三件事，一个都不能少：

1. 搜了什么关键词
2. 搜了多大半径（试着放宽到了多少）
3. 结果确实是 0

然后给具体建议：换关键词（「咖啡馆」→「咖啡」/「咖啡厅」）、扩大范围、换起点。

⛔ **一个地点都不许编。** 宁可不推荐，也不能给一个查不到的名字。题目对无结果用例的判据是「是否正确处理」，**推荐数量为零不扣分**，但编造一定扣分。

### ③ 工具调用失败

说「高德服务这次没有返回结果」，**不要说「附近没有咖啡馆」**。

这两句是两件事：

- **服务故障**：接口报错 / 超时 → 可以说「服务异常，稍后重试」
- **真的没有**：接口正常返回空列表 → 才可以说「附近没找到」

失败时先重试一次，仍失败就如实报，并给用户可自己验证的方式（直接在高德 App 搜同一关键词）。

### ④ 信息未核实（高德不返回的字段）

以下信息一律标「未核实」，⛔ 不能编：

- 营业状态 / 是否营业中
- 排队情况
- 安静程度 / 环境 / 氛围
- 评分 / 好评数
- 人均消费
- 是否有座位 / 是否适合带小孩

写法：`营业状态未核实，建议出发前电话确认`。

### ⑤ 同一起点、多个备选，不是行程规划

题目明说：**各地点都是从同一起点出发的独立备选，不需要串成多站行程。**

⛔ 不要输出「先去 A 再去 B，两地相距 300 米」这种路线串联。每个地点只算「起点 → 该地点」这一段。

## 五、必须避免的六种错误

| ❌ 错误 | ✅ 正确 |
|---|---|
| 「距离约 800 米，步行约 12 分钟」（拿半径或直线距离换算） | 必须调 `maps_direction_walking` 拿真实 `duration` |
| 「步行速度 80 米/分钟，1200 米约 15 分钟」 | 80 米/分钟只用来定**搜索半径**，绝不进回答 |
| 用 `maps_distance` 算出的距离当步行距离 | 用 `maps_direction_walking` 的 `distance` |
| 把超时地点也列出来，标注「略超一点」 | 超时的**不进推荐表** |
| 只做周边搜索就输出，不查步行路线 | 每个入选地点都有一条步行路线调用记录 |
| 用 `maps_text_search` 搜出全城结果当「附近」 | 周边搜索，或明确标注「这是全城结果」 |

## 六、一次完整的正确调用序列

用户：「我在杭州西湖文化广场，想找咖啡馆，步行不超过 15 分钟，最多 3 家，优先近的。」

```
① maps_geo(address="杭州西湖文化广场", city="杭州")
   → return[0].location = "120.1634,30.2798"
   （多条就选 level=兴趣点 的那条，并在回答里写明用了哪一个）

② maps_around_search(location="120.1634,30.2798", keywords="咖啡馆", radius="1200")
   → pois: 6 个候选，字段只有 id / name / address / typecode / photos
   （按 typecode 剔掉便利店、奶茶店，留 6 个）

③ 对这 6 个，每个做两步：
   maps_search_detail(id=候选.id)                        → location
   maps_direction_walking(origin="120.1634,30.2798", destination=该 location)
     → paths[0].distance / paths[0].duration

④ 过滤 duration ≤ 900 秒 → 剩 4 个
   按 duration 升序

⑤ 取前 3 个 → 输出表格 + 一行说明
```

⛔ 如果第 ③ 步没做，第 ⑤ 步表里的任何米数和分钟数都是编的。
