# 算法导论 · 第 3 章：函数的增长与递归式

> 课程：算法设计与分析（本科三年级）
> 本章目标：掌握渐近记号，能用主定理与递归树分析分治算法的运行时间。

## 3.1 渐近记号

当输入规模 n 趋向无穷时，我们忽略常数因子和低阶项，用渐近记号描述算法的增长量级。O 记号给出渐进上界：若存在正常数 c 和 n0，使得对所有 n ≥ n0 都有 0 ≤ f(n) ≤ c·g(n)，则记 f(n) = O(g(n))。Θ 记号同时给出上界和下界，表示 f 与 g 同阶；Ω 记号给出下界。小 o 和小 ω 则分别表示严格小于和严格大于的关系。考试里最常见的错误是把 O 当成「大约等于」，例如把 3n² + 5n 写成 O(n)，这实际上连 Ω 都不满足。正确的写法是 Θ(n²)，或者保守地写 O(n²)。

## 3.2 分治法与递归式

分治法的三步是分解、解决、合并。归并排序把数组对半切开，递归排序左右两半，再用线性时间合并，因此运行时间满足递归式 T(n) = 2T(n/2) + Θ(n)。展开递归树可以看到：第 0 层代价为 cn，第 1 层两棵子树合计仍是 cn，一共有 log₂n 层，所以总代价为 Θ(n log n)。递归树方法的好处是直观，适合快速估算；主定理则给出更正式的结论：对于 T(n) = aT(n/b) + f(n)，比较 f(n) 与 n^(log_b a) 的增长速度即可判定三种情形。归并排序对应第二种情形，答案是 Θ(n log n)。

## 3.3 常见陷阱

递归式中的 n/b 要按整数除法理解，忽略取整只会影响常数。分析空间复杂度时不要忘记递归栈的深度。写证明时先声明 n0 与常数 c，再给出不等式推导，否则会被扣分。另一个常见问题是把最好情况当成平均情况，例如快速排序在有序输入上退化为 O(n²)，而随机化版本期望时间为 O(n log n)。

## 3.4 延伸：索引结构的代价分析

本章的渐近记号同样适用于数据库索引。B+树 的等值查找与范围扫描都是 O(log n)，因为树高随记录数对数增长；而 LSM 结构把随机写转化为顺序写，单次写入很快，但后台合并会带来额外的读写开销。用同一套记号比较两类结构时，要分别写出查找、插入与合并的代价，而不能只看单次操作。后续课程会用实测数据检验这些渐近结论，并讨论聚簇索引与向量检索在不同负载下的取舍。

## 3.5 课堂练习

练习一：对递归式 T(n) = 3T(n/4) + n log n，先用主定理判断属于哪一种情形，再用替换法验证上界。练习二：证明 log(n!) = Θ(n log n)，提示是把求和写成积分并在两端放缩。练习三：比较插入排序与归并排序在小规模输入上的实际耗时，解释为什么渐近更优的算法不一定更快。助教提醒：写答案时要同时给出常数 c 与阈值 n0，只写「显然成立」不得分。

## 3.6 小结

渐近分析的价值在于忽略机器差异，抓住决定增长趋势的主要项；但它不能替代实测，常数因子和缓存行为在小规模数据上同样重要。下一章将把这些工具用于堆排序与快速排序的分析，并结合递归树与主定理反复练习。
