# 验证样例

本样例说明如何从零复现一次完整的 SDD 任务：给出任务描述 → 检索适用规范与代码位置 →
MiniMax 生成改动 → 目标测试由失败转为通过、回归测试保持通过 → 任务状态写入 PowerContext
并在重启后读回。

## 1. 任务

```
订单满 99 元免运费；会员折扣后金额不足 99 元时应按折后金额判断，金卡会员始终免运费。
```

业务背景：结算服务 `workspace/src/pricing/engine.py` 的 `shipping` 实现与规范 S-04 不一致：

- 用**折前金额**判断包邮门槛，且用严格大于 `>`，导致正好 99.00 元的订单被收 8.00 元运费；
- 会员折扣后的金额低于 99 元时仍按折前金额免运费（例如 100 元 silver 会员折后 95 元却免运费）；
- 完全没有处理金卡会员。

任务要求只修改该逻辑，不改变 `settle` 的返回字段与其他计算规则。

## 2. 适用规范条款

规范文件：`workspace/specs/pricing_rules.md`（版本 2026-10-27，条款编号 `S-01`～`S-05`）。

主条款 **S-04 运费**（`workspace/specs/pricing_rules.md:25-28`）：

> 订单包邮门槛按“会员折扣后金额”判断：折后金额大于等于 99.00 元时免运费；低于
> 99.00 元收取 8.00 元运费。`gold` 会员始终免运费。

上下文同时给出关联条款，便于核对计算顺序与返回结构：

- **S-02 会员折扣**（`workspace/specs/pricing_rules.md:14-18`）：gold 10%、silver 5%、none 0%；
  折扣金额四舍五入保留两位小数；未知等级抛 `ValueError`。
- **S-03 优惠券**（`workspace/specs/pricing_rules.md:20-23`）：优惠券在会员折扣之后抵扣，
  抵扣后金额不得为负。
- **S-01 订单小计**（`workspace/specs/pricing_rules.md:8-12`）与
  **S-05 应付总额**（`workspace/specs/pricing_rules.md:30-33`）：金额使用 `Decimal`，
  应付总额 = `max(0, 小计 − 会员折扣 − 优惠券) + 运费`。

这些条款来自 `sdd select` 的实际输出（`evidence/context-latest.md`、`context-latest.json`），
引用位置均可在文件中逐行核对。

## 3. 初始数据

初始状态由以下文件构成（`python scripts/reset.py` 可随时恢复）：

| 文件 | 说明 |
| --- | --- |
| `workspace/specs/pricing_rules.md` | 5 条带编号的结算规范 |
| `workspace/src/pricing/engine.py` | 有缺陷的结算实现（`evidence/before/engine.py` 为快照） |
| `workspace/src/pricing/__init__.py` | 导出 `settle` |
| `workspace/tests/test_engine.py` | 8 个回归测试 |
| `workspace/tests/test_shipping.py` | 3 个目标测试（改动前应当失败） |
| `workspace/pyproject.toml` | pytest 配置（`pythonpath = ["src"]`） |

改动前的关键代码（`workspace/src/pricing/engine.py`，`shipping` 函数）：

```python
def shipping(amount_before_discount: Decimal, tier: str, amount_after_discount: Decimal) -> Decimal:
    """Return the shipping fee for an order (S-04). ..."""
    if amount_before_discount > FREE_SHIPPING_THRESHOLD:
        return ZERO
    return SHIPPING_FEE
```

此时 `settle` 中的调用为 `fee = shipping(total, tier, after_discount)`。

目标测试（3 个，覆盖 S-04，改动前失败）：

- `workspace/tests/test_shipping.py::test_shipping_is_free_at_the_exact_threshold`
- `workspace/tests/test_shipping.py::test_shipping_uses_the_post_discount_amount`
- `workspace/tests/test_shipping.py::test_gold_members_always_get_free_shipping`

回归测试（8 个，覆盖 S-01/S-02/S-03/S-05，改动前后都必须通过）：
见 `evidence/context-latest.json` 的 `tests.regression` 与 `evidence/pytest-before.log` 的 PASSED 列表。

材料索引由 `sdd ingest` 建立：5 条规范条款、7 个代码符号、11 个测试函数
（见 `evidence/demo-summary.json` 的 `ingest.counts`）。

## 4. 复现步骤

### 4.1 一键复现（推荐）

Linux（评分环境，seekdb 索引）：

```bash
cd minimax
python scripts/demo.py --backend seekdb
```

Windows（无 seekdb 轮子，使用同构 SQLite 后端）：

```powershell
cd minimax
python scripts\demo.py --backend sqlite
```

脚本会自行启动 PowerContext Server（隔离的 `POWERCONTEXT_HOME`、自动挑选空闲端口），
按顺序完成初始化、检索、改动前测试、应用 MiniMax 改动、验证、重启后读回状态。
任意一步与预期不符即以退出码 1 失败，并保留当次日志。

### 4.2 手工分步（便于逐步核对）

```bash
# 0) 恢复初始状态
python scripts/reset.py

# 1) 启动 PowerContext Server（另开终端；或使用 scripts/start-server.sh）
python -c "import sys; from powercontext.cli.app import main; raise SystemExit(main())" \
    server run --no-env-file --port 8137

# 2) 导入规范 / 代码 / 测试
python -m sdd ingest --backend seekdb

# 3) 生成开发上下文，并把任务状态写入 PowerContext
python -m sdd select --backend seekdb \
  --task "订单满 99 元免运费；会员折扣后金额不足 99 元时应按折后金额判断，金卡会员始终免运费。" \
  --remember --out evidence/context-latest

# 4) 改动前：目标测试应失败
cd workspace && python -m pytest -v -rA tests; cd ..

# 5) 应用 MiniMax 生成的改动
cp evidence/after/engine.py workspace/src/pricing/engine.py

# 6) 验证并回写状态
python -m sdd verify --backend seekdb \
  --task "订单满 99 元免运费；会员折扣后金额不足 99 元时应按折后金额判断，金卡会员始终免运费。" \
  --log evidence/pytest-after.log --require-state

# 7) 重启 Server（停掉第 1 步的进程后重新启动），再读取状态
python -m sdd state --backend seekdb
```

## 5. 规范更新后的重新导入

比赛要求“更新规范并重新导入后，输出应使用更新后的内容”。这一步单独验证，不会改动真实工作区：

```bash
python scripts/spec_update_check.py --backend seekdb   # Windows 用 --backend sqlite
```

脚本的动作与预期：

1. 把 `workspace/` 复制到临时目录，只把 S-04 正文中的 `99.00` 改成 `120.00`；
2. 对临时副本执行 `sdd ingest`（5 条款 / 7 符号 / 11 测试）；
3. 用同一个任务描述执行 `sdd select`，读取输出的 JSON 与 Markdown；
4. 断言选中的 S-04 正文包含 `120.00`、不再包含 `99.00`，且主条款仍是 `S-04`。

实际输出（`evidence/spec-update-check.log`）：

```json
{
  "ok": true,
  "backend": "seekdb",
  "spec_counts": {"spec_clauses": 5, "code_symbols": 7, "tests": 11, "context_runs": 0},
```

## 7. 重置

回到初始状态（保留依赖安装与证据文件）：

```bash
python scripts/reset.py            # 恢复 evidence/before/engine.py，删除 .data/ 与 run/
python scripts/reset.py --keep-data  # 只恢复代码，保留索引与 PowerContext 数据
```

或直接用版本控制恢复业务代码：

```bash
cp evidence/before/engine.py workspace/src/pricing/engine.py
```

重置后重新执行 `scripts/demo.py` 即可从头复现。
