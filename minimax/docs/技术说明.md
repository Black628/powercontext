# 一页技术说明

## 目标

在「规范（Spec）→ 代码（Code）→ 测试（Test）」之间建立可复核的上下文链路：给定一个开发任务，
系统必须给出本次改动**依据哪几条规范条款、要改哪些代码位置、哪些测试必须由失败转为通过、
哪些测试必须保持通过**，并在任务推进过程中持久化已完成项、待办项与验证结果，重启后仍可复用。
本提交用一个可运行的结算服务 `pricing` 演示该链路：规范 S-04 要求按会员折扣后金额判断包邮
门槛（≥ 99 元免运费、金卡始终免运费），现有实现按折前金额且用严格大于判断，任务即为修复它。

## 模块结构

```
sdd/
  cli.py       入口：ingest / select / verify / state / info（JSON 输出，退出码可脚本化）
  config.py    路径与后端配置（环境变量 SDD_*、POWERCONTEXT_*）
  parser.py    规范条款 / 代码符号 / 测试解析，行号与内容摘要
  keywords.py  中英文关键词抽取（ASCII 词 + CJK bigram，标题加权）
  store.py     材料索引（seekdb / SQLite 同构 SQL），每次查询写 SQL 日志
  select.py    检索、排序、引用合并、上下文渲染（JSON / Markdown / 提示词）
  pc.py        PowerContext HTTP 客户端（Scope + Atomic Memory 任务状态）
workspace/     演示业务项目（规范、实现、8 个回归测试、3 个目标测试）
scripts/       demo.py 端到端复现、reset.py、start-server.*
```

## 上下文选择

1. **导入**：解析 `## S-XX` 条款（条号、标题、正文、`path:line_start-line_end`），`ast` 解析函数/
   类/方法（限定名、签名、docstring 中引用的条款号），解析 `test_*` 函数及其 `Covers: S-XX`。
   条款、符号、测试分别切词后写入关键词表（标题词权重 ×3，单关键词权重上限 5）。
2. **检索**：任务描述切词（上限 40 个），与关键词表按权重求和打分；任务中显式出现的条号直接
   加 100 分。取最高分条款为主条款，其余按分数排序，默认最多 8 条。
3. **定位代码**：符号按关键词匹配得分，docstring 引用主条款的符号额外加 5 分，保证“条款 → 符号”
   不依赖关键词是否偶然命中；输出符号的签名与 `path:line`。
4. **划分测试**：`Covers` 与主条款相交的测试为目标测试（改动后必须由失败转为通过），其余测试为
   回归测试（改动前后都必须通过）。两者都带 `path:line` 引用。
5. **一致性校验**：重新读取条款文件，若条款内容摘要与导入时不一致则输出警告，提示重新 `ingest`，
   避免规范更新后继续使用过期上下文（更新规范 → 重新导入 → 新条款立即生效；可用
   `scripts/spec_update_check.py` 复现，证据 `evidence/spec-update-check.log`）。
6. **渲染**：同一份上下文输出 JSON（机器消费）、Markdown（评审阅读）、紧凑提示词（交给 MiniMax）。

## 三项技术分工

| 技术 | 角色 | 证据 |
| --- | --- | --- |
| MiniMax（`minimax-cn` / `MiniMax-M3`） | 读取上下文提示词，生成 `shipping` 的修复代码（折后金额、`>=`、金卡分支、调用点同步） | `evidence/minimax-raw-reply.md`（原始回复）、`evidence/diff.patch`（逐行对应） |
| seekdb（`pylibseekdb 1.4.0.post1` + `pymysql`） | 存储并查询规范条款、关键词、代码符号、测试与运行记录；`ingest`/`select` 的每次 SQL 写入 `.data/logs/sql.log` | `scripts/demo.py --backend seekdb` 生成的 SQL 日志与 `ingest` 计数 |
| PowerContext 1.4.1 | 保存任务状态（目标、已完成/待办、验证记录）并在 Server 重启后读回 | `.data/logs/powercontext.log` 中的 Scope / Atomic Memory 请求与 `demo-summary.json` 的重启读回结果 |

Windows 上没有 seekdb 轮子，`store.py` 提供同构的 SQLite 后端（`--backend sqlite`），便于本地演示；
评分环境（Linux）使用 seekdb。

## 状态模型

PowerContext 中一个 Scope（`minimax-sdd-pricing`）对应一个任务，状态存为 `atomic-memory` 家族的
`kind = sdd-task-state` Artifact，正文为 JSON：`objective`、`status`（`in-progress`/`verified`）、
`primary_clauses`、`selected`（条款 / 符号 / 目标测试 / 回归测试 ID）、`completed`、`pending`、
`verification`（每次验证的命令、通过名单、时间）。首次写入创建 Artifact，之后用
`If-Match: "revision:N"` 追加新修订，避免并发覆盖；读取走 `POST /v1/atomic-memory/list`，
兼容 PowerContext 1.4.x 对旧版 Memory collection 的停用。

## 权衡与限制

- 关键词检索不引入向量模型，换取零外部依赖与可解释性；规模变大时可替换 `keywords.py`。
- seekdb 仅支持 Linux/macOS，且数据库目录需在原生文件系统；Windows 走 SQLite。
- 演示任务只有 5 条规范、7 个符号、11 个测试，选择结果可人工逐条核对；引用均来自真实文件与行号。
